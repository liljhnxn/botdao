Executive Summary

Emerging blockchain ecosystems face a critical hurdle: early-stage community funds, developer grants, and ecosystem treasuries remain controlled by opaque multisigs or centralized foundations. This undermines community trust and stalls grassroots innovation.

BotDAO provides the foundational governance and treasury primitive for the Botchain ecosystem. It introduces a trustless, transparent on-chain treasury where community members deposit native BOT tokens, submit granular funding proposals, vote transparently, and automatically trigger non-custodial payouts upon reaching quorum and approval.

🛡️
100% Non-Custodial
No admin backdoors or owner withdrawal keys. Treasury funds leave the contract strictly through passed community proposals.
🗳️
Democratic Voting
1-wallet = 1-vote mechanism with immutable on-chain records and double-voting prevention.
⚡
Trustless Execution
Anyone can trigger execution. Approved BOT funds transfer directly to the recipient without intermediaries.

The Problem & Market Need

  • Opaque Fund Allocation: Token holders have zero real-time visibility into treasury balances or approval conditions.
The BotDAO Solution
  • Automated Smart Contract Vault: Native BOT pooling with instant on-chain balance tracking.
  • Turnkey User Experience: Clean Web3 application tailored specifically to Botchain RPC and Explorer.
  • Guaranteed Payouts: Smart contracts strictly enforce quorum and majority checks before disbursing funds.

System Architecture & Governance Lifecycle

The complete lifecycle of a BotDAO proposal is governed deterministically on-chain:

1. Deposit Treasury funded with native BOT
→
2. Propose Submit amount, recipient & duration
→
3. Vote 1-Wallet = 1-Vote (FOR / AGAINST)
→
4. Conclude Quorum & Majority verified
→
5. Execute Public trigger disburses BOT
Mathematical Passing Condition:
A proposal ID p is considered passed if and only if:
block.timestamp >= p.endTime  AND  (p.forVotes + p.againstVotes) >= quorumVotes  AND  p.forVotes > p.againstVotes

Smart Contract & Technical Specifications

The core engine is implemented in Solidity ^0.8.24 with audited OpenZeppelin primitives.

Function / Method Type Description
depositTreasury() External Payable Allows any wallet to deposit native BOT directly into the non-custodial DAO vault.
createProposal(...) External Submits a proposal specifying recipient address, requested BOT, description, and duration.
vote(id, support) External Casts an immutable FOR or AGAINST vote with double-vote prevention.
proposalPassed(id) Public View Pure on-chain verification of voting deadline, quorum compliance, and positive majority.
executeProposal(id) External (Reentrant Safe) Disburses BOT to the recipient. Protected by OpenZeppelin's ReentrancyGuard.
cancelProposal(id) External Allows the proposal creator to cancel an active, unexecuted proposal.
getAllProposals() External View High-performance batch reader returning all proposals in a single RPC call.

Security & Risk Analysis

  • Zero Custodial Backdoors: No administrator, deployer, or multisig can withdraw or redirect treasury funds without a formal on-chain vote.
  • Reentrancy Resistance: Strict adherence to Checks-Effects-Interactions (CEI) alongside OpenZeppelin's battle-tested ReentrancyGuard.
  • Comprehensive Test Coverage: Hardhat automated test suites cover deposit dynamics, boundary conditions, quorum edge cases, double-voting rejection, and reentrancy safety.
